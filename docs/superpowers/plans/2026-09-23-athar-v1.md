# Athar v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Athar v1: a single Windows `athar.exe` that archives every local AI-agent conversation into a permanent SQLite archive, searches it (Arabic-aware), and reads/resumes sessions from a one-screen TUI.

**Architecture:** Go module `github.com/AbuDergham/Athar`. Adapters (one file per agent) read agent stores read-only and emit `model.Session`s; `syncer` fingerprints sources and applies results to `archive` (SQLite + FTS5 trigram, never-delete rules); `tui` (Bubble Tea v2) queries the archive and uses `launch` (Windows Terminal tabs), `render` (HTML reading page) and `update` (signed self-update). The compiling skeleton with every package contract is already committed; tasks fill in the stubs.

**Tech Stack:** Go ≥ 1.25 (build machine: portable Go 1.27.1 at `C:\Users\X\sdk\go\bin`), `charm.land/bubbletea/v2` v2.0.9, `charm.land/bubbles/v2`, `charm.land/lipgloss/v2`, `modernc.org/sqlite` v1.59.0 (SQLite 3.53.4, FTS5 + trigram), `github.com/klauspost/compress/zstd`, `google.golang.org/protobuf/encoding/protowire`, `aead.dev/minisign`, `golang.org/x/text`, `golang.org/x/sys/windows`, `github.com/BurntSushi/toml`.

**Spec:** `docs/superpowers/specs/2026-09-23-athar-design.md` (rev. 2). Read it before any task; section numbers below refer to it.

## Global Constraints

- Every task's requirements include the spec. Where this plan and the spec differ, the spec wins; report the difference.
- **Read-only toward agents (spec §1 P4, §4.3, §10):** never write/create/lock-against-delete anything in agent folders; JSON/JSONL through `fsread.Open`/`fsread.Lines`; SQLite only through `fsread.CopySQLite`. Never execute agent binaries (lookups only). Never run `freebuff` or `kilo` for any reason.
- **Privacy:** test fixtures are synthetic. Never copy real conversation text, titles, usernames or paths from the owner's machine into the repo. Real-data checks print statistics only (`go run ./tools/dump <id>`).
- **Contracts are fixed:** do not change exported signatures in `internal/model`, `internal/adapters/adapter.go` or other packages' stubs without reporting it; add new exported helpers freely inside your own package.
- **Dependencies:** only those in go.mod. Do NOT run `go mod tidy` (the orchestrator does). If a build needs a go.sum entry, run `go mod download <module>`.
- **Git:** do NOT commit; the orchestrator commits after each phase. Touch only the files of your task (plus your package's `testdata/`).
- **Go toolchain:** `export PATH="/c/Users/X/sdk/go/bin:$PATH"` (Git Bash) or `$env:Path = "C:\Users\X\sdk\go\bin;$env:Path"` (PowerShell).
- **Done means:** `go build ./...`, `go vet ./...` and `go test ./internal/<pkg>/...` pass, and the task's checklist is met.
- Style: small focused files, doc comments on exported identifiers, table-driven tests, no global mutable state except documented package vars.

### Task 1: fsread — share-friendly reading and SQLite temp copies

**Files:** Modify `internal/fsread/fsread.go` (split into `open_windows.go`, `open_other.go`, `lines.go`, `sqlite.go`, `fingerprint.go` as useful). Tests: `internal/fsread/*_test.go`.

**Interfaces:** Produces exactly the functions declared in the stub.

- [ ] `Open`: on Windows use `windows.CreateFile` with `GENERIC_READ`, `FILE_SHARE_READ|FILE_SHARE_WRITE|FILE_SHARE_DELETE`, `OPEN_EXISTING`, `FILE_ATTRIBUTE_NORMAL`, wrap with `os.NewFile`. Non-Windows: `os.Open`.
- [ ] `Lines`: `bufio.NewReaderSize(f, 1<<20)` + `ReadSlice`/`ReadBytes('\n')`, strip `\r\n`/`\n`; do not deliver a final unterminated line; skip empty lines; stop on fn error.
- [ ] `ZstdLines`: `zstd.NewReader` streaming over `Open`, same line rules (a final line without newline IS delivered for compressed files, since they are written whole).
- [ ] `Stat`/`Fingerprint`: `os.Stat` (does not open for write). Fingerprint = `path|size|mtimeUnixNano;` concatenated for existing files, then SHA-256 hex.
- [ ] `SQLiteSidecars`: db + existing `-wal`, `-shm`.
- [ ] `CopySQLite`: `os.MkdirTemp(tempDir, "sq-")`; copy each sidecar through `Open` (not os.Open); open the COPY with `modernc.org/sqlite` DSN `file:<copy>?mode=ro&immutable=1` — careful: with `-wal` present immutable ignores the WAL, so instead open the copy read-write (it is our private copy) so SQLite replays the WAL, run `PRAGMA quick_check`; if not "ok", retry the whole copy up to 3 times; return copy path and cleanup (RemoveAll).
- [ ] Tests (write first, see them fail, then implement):
  - a 3 MB single-line JSONL is delivered as one line; unterminated last line not delivered; CRLF stripped.
  - while `Open` holds a file, `os.Remove` and `os.Rename` of that file succeed (Windows).
  - `CopySQLite` on a WAL-mode fixture DB with un-checkpointed rows: the copy sees the rows; afterwards the SOURCE folder has identical file list, sizes and mtimes (read-only guarantee), and no new `-wal`/`-shm` appeared.
  - `Fingerprint` changes when size or mtime changes, ignores missing files.
- [ ] Run `go test ./internal/fsread/...` → PASS.

### Task 3: archive — schema, never-delete apply, search queries, backups (after Task 2)

**Files:** Modify `internal/archive/archive.go`; create `schema.go`, `apply.go`, `query.go`, `backup.go`, `project.go`; tests `*_test.go`.

**Consumes:** `search.Normalize`, `search.Parse`, `model.*`. **Produces:** the stub API exactly.

- [ ] Schema (spec §4.2) with `schema_version` in `meta`; `PRAGMA journal_mode=WAL; foreign_keys=ON; busy_timeout=5000`. Tables `sources`, `sessions`, `messages(id, session_id, seq, role, kind, at, text, text_hash)`, `fts_msg` = `CREATE VIRTUAL TABLE fts_msg USING fts5(body, content='', contentless_delete=1, tokenize='trigram')` with rowid = messages.id and body = `search.Normalize(text)` (for tool_output only first 2 KB), `fts_title` = same over `Normalize(title + " " + project_name)` with rowid = sessions.id. Thinking is never stored.
- [ ] `Open`: if the file exists but fails to open / `quick_check` ≠ ok → return an `*ErrDamaged{Path, Err, Backups []string}` (never recreate). Before migrating an existing schema, call `Backup`.
- [ ] `ApplySource` rules (spec §4.4–4.5), one transaction:
  1. upsert `sources` row (machine, path) with fingerprint, adapter_version, last_ok_at, skipped, warnings JSON, last_error cleared.
  2. For each session: look up by (agent, native_id). New → insert with ProjectPath (walk up from Cwd to a dir containing `.git`, stop at volume root; never run git), ProjectName rules (§3.4: `~` for home, `D:` for drive root, `(no project)` when Cwd empty), then messages + FTS rows.
  3. Existing → priority: incoming origin `live` beats imports/prompt-log; an import/prompt-log never replaces messages of a live session with more messages; it may fill title/cwd if empty. Stored non-empty Cwd is never overwritten. Title: replace if incoming TitleSource rank (user>agent>prompt>none) ≥ stored. StartedAt = min, UpdatedAt = max, Coverage = max rank. Set source_id to this source, clear source_missing_at, set machine to rec.Machine (or session.Machine when non-empty).
  4. Messages: compute `text_hash = sha256(role|kind|text)[:16]`. If stored hashes are a prefix of incoming → append the tail. Else → keep stored, append incoming messages whose (role, hash) is not stored, increment `Shrunk`. Keep FTS in sync (insert for new rows only; never delete).
- [ ] `FinishSync(machine, seenPaths)`: for sessions whose source (on this machine) path ∉ seenPaths and no other seen source contains the session → `source_missing_at = at`. Sources not seen are kept (history) but flagged missing.
- [ ] `Search(Filter)`:
  - Empty query → timeline: `ORDER BY updated_at DESC` with Agent/Since filters, `HitSeq=-1`.
  - Non-empty: `terms := search.Parse(q)`. For each non-short term: `SELECT rowid FROM fts_msg WHERE fts_msg MATCH '"<escaped>"'` → message ids → session ids; plus `fts_title` matches → session ids. Phrase terms: same (trigram phrase = substring). Short terms (<3 runes): `LIKE` on normalized title/project stored in a `sessions.norm_title` column. For each session count matched terms; rows with all terms first, then partial (MatchedTerms desc), each group ordered by (best bm25 asc via `bm25(fts_msg)`, then updated_at desc). Pick HitSeq = message matching most terms (ties bm25). Snippet from ORIGINAL text: find the match position in the normalized text of that message and map back (keep an index map from normalized rune index → original rune index built during a re-normalization of that one message), return ~60 runes around it with `…`.
  - Apply Agent/Since filters; limit/offset.
- [ ] `Messages`, `HitSeqs`, `Agents`, `Sources`, `Meta`, `SetMeta`, `Path`, `Backup` (`VACUUM INTO dir/archive-YYYY-MM-DD.db`, keep newest 2).
- [ ] Tests (fixtures built in Go, temp dirs):
  - apply → search finds Arabic variants (مشروع ⇢ بمشروعي, احمد ⇢ أحمد) and English substrings; per-session AND across two different messages; partial-match fallback reports MatchedTerms; phrase must be in one message; 2-char term matches title only.
  - shrink: apply 5 messages then 3 different → 8 stored, Shrunk=1; apply prefix-extended list → appended, not duplicated.
  - live vs import dedup; prompt-log merged into a full session; Cwd not overwritten; title priority.
  - FinishSync marks missing only when unseen everywhere; session moved to another path is not marked.
  - damaged file → ErrDamaged, file untouched.
  - timeline order and Since filter; snippet contains original diacritics.
- [ ] Benchmark note: build an archive from the owner's real data via Task 12 later; record size in the report.

## Phase 2 — Adapters (parallel; each only touches its own files + `testdata/<id>/`)

Every adapter lives in its OWN package `internal/adapters/<id>/` (package name = id, e.g. `package codex`) so parallel work never breaks another adapter's build. Fixtures go in `internal/adapters/<id>/testdata/`. The orchestrator adds `<id>.New()` to `internal/registry/registry.go`. Shared test helpers: `internal/adapters/adapterstest` (`FixtureEnv`, `ReadAll`, `RealData`). Every adapter package has `func TestRealData(t *testing.T) { adapterstest.RealData(t, New()) }` (skipped unless `ATHAR_REALDATA=1`; prints statistics only).

Common pattern for every adapter task:

```go
package codex

type adapter struct{}
// New returns the Codex adapter (used by internal/registry).
func New() adapters.Adapter { return adapter{} }
func (adapter) ID() string   { return "codex" }
func (adapter) Name() string { return "Codex" }
func (adapter) Version() int { return 1 }
func (adapter) Sources(env adapters.Env) ([]adapters.Source, error) { … }
func (adapter) Read(ctx context.Context, env adapters.Env, src adapters.Source) (adapters.ReadResult, error) { … }
func (adapter) Caps() adapters.Caps { … }
```

Each adapter task: (1) inspect the REAL local files for structure only (keys, table names, shapes) — never copy text; (2) create a small synthetic fixture tree under `internal/adapters/<id>/testdata/` reproducing that structure (JSONL adapters include one ~2 MB single-line record; SQLite adapters include a WAL-mode fixture DB built by the test itself in a temp dir from a SQL script, not a committed binary where avoidable); (3) failing golden test; (4) implement; (5) `go test ./internal/adapters/<id>/`; (6) `ATHAR_REALDATA=1 go test ./internal/adapters/<id>/ -run TestRealData -v` and report the statistics line (sessions, coverage, noCwd, date range, errors).
